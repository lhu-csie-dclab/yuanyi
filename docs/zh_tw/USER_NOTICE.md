# 📋 使用者須知 — 加入 Swarm 前請務必閱讀

> [!WARNING]
> **本專案為實驗階段的研究軟體。** 以下描述的是它目前的實際行為。
> **沒有任何隱私保證、沒有安全服務等級承諾、沒有任何擔保。**
> 請勿用它處理任何「被公開你會承受不起」的資料。

加入 Swarm 等於和其他人共用機器。這份文件把你**放棄了什麼**、以及**扛下了什麼**講清楚，
讓你在加入之前就能判斷，而不是加入之後才發現。

---

## 1. 你的機器每 3 秒向所有節點廣播遙測資料

每個節點都會持續把自己的狀態廣播給整個 Swarm。**這是強制的，無法關閉**，
而且 Swarm 裡的每一個成員都會收到全部內容。

| 廣播內容 | 實際洩漏了什麼 |
| :--- | :--- |
| `addr`（libp2p multiaddress） | **你的 IP 位址**，進而可推知你的大致地理位置與 ISP |
| `node_id`（PeerID） | 一個**重開機也不會變的長期識別碼**（存在 `identity.key`），你的活動可被長期關聯追蹤 |
| `summary`、`vram_total`、`driver_version` | 你的**顯卡型號、VRAM 容量、驅動版本** —— 可用於硬體指紋辨識 |
| `gpu_temp`、`gpu_util`、`power_draw`、`power_limit`、`fan_speed` | 即時硬體遙測數據 |
| `total_requests`、`total_tokens`、`in_tokens`、`out_tokens` | **你使用這套系統的量有多大** |
| `status`、`active_requests`、`timestamp` | **你的機器何時在運作** —— 長期累積下來就是你的作息／使用時段 |
| `gen_speed`、`prefill_speed`、`avg_ttft`、`kv_cache_usage` | 效能特徵數據 |

**這些資料還會被儲存與公開：**

- 任何開啟 **Hub 模式**的節點，都會把你的 PeerID、**IP 位址**與遙測資料寫進它本機的
  SQLite 資料庫（`peers.db`）並保存下來。**你無從得知誰在這樣做，也無法要求對方刪除。**
- Hub 節點會發布**公開的貢獻度排行榜**（`top.json` 與儀表板頁面），依 GPU 能力排名所有參與者。

Prompt 的**內容本身**不包含在這份遙測裡 —— 但上表的所有項目都會被廣播出去。

## 2. 你同樣會收到所有其他人的遙測資料

這個交換是雙向對等的。你的節點也會蒐集其他每一位參與者的相同資料並存在本機。

⚠️ **如果你開啟 Hub 模式，你等於在把別人的 IP 位址持續寫進你的硬碟。**
這在你所在司法管轄區可能觸及個資相關法規義務（台灣個資法、GDPR、PIPA 等）。
開啟 Hub 模式前請先考慮這一點。

## 3. 你的 Prompt 可能以明文離開你的電腦

當你本機 GPU 忙碌時，你的請求會被分發到**別人的機器**上執行；那台機器**必須解密**才能做推論。
該節點的營運者可以完整讀取你的 Prompt 以及模型的回應。

傳輸加密保護的是「網路上的第三方竊聽」，**無法保護你不被執行推論的那台機器看見**。
這是無法迴避的 —— 推論必然需要明文。

👉 完整說明與信任模型：**[`SECURITY.md`](../SECURITY.md)**

**因此：絕對不要在共用的 Swarm 裡輸入任何「你不願意讓其他所有營運者看到」的內容。**
密碼、個人資料、醫療或財務資訊、公司專有程式碼、未發表的研究 —— 都不要放進去。

## 4. 別人的 Prompt 會在你的 GPU 上執行

反過來也同樣成立，而且很容易被忽略：

- **你無法控制其他參與者送進你硬體的是什麼內容。** 那可能是冒犯性的、
  甚至在你所在國家是違法的內容。它會用**你的 GPU**、**你的電費**、
  在**你的 IP 位址**底下被處理。
- **你的硬體會被別人消耗。** 只要你的節點閒置到足以接受工作，就會產生耗電、發熱與硬體損耗。
- 如果你的設備受到**學校或公司規範**限制可處理的內容，加入公開 Swarm 可能違反規定。請先確認。

## 5. 分享 `swarm.key` 就等於交出全部的安全邊界

`swarm.key` 決定的是**誰能加入**，**不會**限制成員加入之後能做什麼。
把金鑰交給某人，就等於永久給了對方（直到你更換金鑰為止）：

- 讀取所有被分發到他手上的 Prompt 的能力
- 你的 IP 位址、硬體指紋與使用習慣
- 消耗你 GPU 的能力
- 把任意內容送進你硬體執行的能力

**請把「分享 `swarm.key`」視同「授予對方讀取你使用者資料的權限」** —— 因為實際效果就是如此。

分享金鑰前請先自問：

- 我真的信任這個人**以及他機器的資安狀況**嗎？
- 如果他的機器被入侵、或他離開這個團隊，會發生什麼事？
- 我有更換金鑰的計畫嗎？（更換金鑰需要**同步更新每一個節點**。）
- 依照我所屬單位的規定，我有權分享這把金鑰嗎？

## 6. 如果你使用的是公共或廣泛流通的金鑰

請假設**所有東西都會被陌生人看到**：

- ✅ 適合：效能測試、功能測試、公開／合成資料、用完即丟的測試 Prompt
- ❌ 不適合：個人資訊、帳號密碼、客戶或病患資料、公司專有內容、任何機密資訊

另外請注意，儀表板（`:50007`）、API 閘道（`:50006`）與 vLLM（`:8100`）**都沒有身分驗證**。
任何能連到你機器這些連接埠的人，都能使用你的 GPU、讀取你節點的設定與日誌。
**請勿將這些連接埠直接暴露在公開網際網路上** —— 詳見 [`SECURITY.md`](../SECURITY.md)。

## 7. 如果以上你無法接受 —— 你仍然可以使用這套軟體

你**不需要**加入共用 Swarm 也能使用本專案：

- **單機獨立執行。** 沒有任何 Peer 的節點依然能用自己的 GPU 提供推論服務。
  不會分發任何請求出去，也不會對任何人廣播。
- **只當中繼站貢獻。** 把 `server_mode.relay_only` 設為 `true`，就能加入並幫助網路，但完全不執行推論。不會用到 GPU，而且**別人的 Prompt 永遠不會在你的硬體上執行** —— 中繼轉發的是**已加密**的串流，中繼者讀不到內容。這等於完全消除第 4 節、以及第 3 節的大部分風險。詳見 [`HUB_MODE.md`](HUB_MODE.md)。
- **建立私有 Swarm。** 金鑰只分享給你或你的單位所掌控的機器。
  這樣上述所有風險就都被限縮在你本來就接受的信任範圍之內。

本文件所列的風險，**專指「與你無法掌控的人共用同一個 Swarm」的情境**。

## 重點總覽

| 項目 | 狀況 |
| :--- | :--- |
| 你的 IP、顯卡型號、使用習慣 | 📡 每 3 秒廣播給所有 Peer，並被 Hub 節點長期儲存 |
| 你的 Prompt | ⚠️ 執行它的那個節點可完整讀取 |
| 別人的 Prompt | ⚠️ 會在你的 GPU 上執行，內容不受你控制 |
| `swarm.key` | 🔑 只管「誰能進來」，進來之後就是完全受信任 |
| 儀表板／閘道／vLLM 連接埠 | 🔓 完全沒有身分驗證 |
| 成熟度 | 🧪 實驗階段 —— 不提供任何形式的保證 |

**請勿透過你無法完全掌控的 Swarm，傳送任何個人隱私或機密資訊。**
