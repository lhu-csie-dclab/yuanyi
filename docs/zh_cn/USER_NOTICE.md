# 📋 用户须知 — 加入 Swarm 前请务必阅读

> [!WARNING]
> **本项目为实验阶段的研究软件。** 以下描述的是它目前的实际行为。
> **没有任何隐私保证、没有安全服务等级承诺、没有任何担保。**
> 请勿用它处理任何「被公开你会承受不起」的数据。

加入 Swarm 等于和其他人共用机器。这份文档把你**放弃了什么**、以及**扛下了什么**讲清楚，
让你在加入之前就能判断，而不是加入之后才发现。

---

## 1. 你的机器每 3 秒向所有节点广播遥测数据

每个节点都会持续把自己的状态广播给整个 Swarm。**这是强制的，无法关闭**，
而且 Swarm 里的每一个成员都会收到全部内容。

| 广播内容 | 实际泄漏了什么 |
| :--- | :--- |
| `addr`（libp2p multiaddress） | **你的 IP 地址**，进而可推知你的大致地理位置与 ISP |
| `node_id`（PeerID） | 一个**重启也不会变的长期标识符**（存在 `identity.key`），你的活动可被长期关联追踪 |
| `summary`、`vram_total`、`driver_version` | 你的**显卡型号、显存容量、驱动版本** —— 可用于硬件指纹识别 |
| `gpu_temp`、`gpu_util`、`power_draw`、`power_limit`、`fan_speed` | 实时硬件遥测数据 |
| `total_requests`、`total_tokens`、`in_tokens`、`out_tokens` | **你使用这套系统的量有多大** |
| `status`、`active_requests`、`timestamp` | **你的机器何时在运作** —— 长期累积下来就是你的作息／使用时段 |
| `gen_speed`、`prefill_speed`、`avg_ttft`、`kv_cache_usage` | 性能特征数据 |

**这些数据还会被存储与公开：**

- 任何开启 **Hub 模式**的节点，都会把你的 PeerID、**IP 地址**与遥测数据写进它本机的
  SQLite 数据库（`peers.db`）并保存下来。**你无从得知谁在这样做，也无法要求对方删除。**
- Hub 节点会发布**公开的贡献度排行榜**（`top.json` 与仪表板页面），依 GPU 能力排名所有参与者。

Prompt 的**内容本身**不包含在这份遥测里 —— 但上表的所有项目都会被广播出去。

## 2. 你同样会收到所有其他人的遥测数据

这个交换是双向对等的。你的节点也会收集其他每一位参与者的相同数据并存在本机。

⚠️ **如果你开启 Hub 模式，你等于在把别人的 IP 地址持续写进你的硬盘。**
这在你所在司法管辖区可能触及个人信息相关法规义务（GDPR、PIPA、个人信息保护法等）。
开启 Hub 模式前请先考虑这一点。

## 3. 你的 Prompt 可能以明文离开你的电脑

当你本机 GPU 忙碌时，你的请求会被分发到**别人的机器**上执行；那台机器**必须解密**才能做推理。
该节点的运营者可以完整读取你的 Prompt 以及模型的响应。

传输加密保护的是「网络上的第三方窃听」，**无法保护你不被执行推理的那台机器看见**。
这是无法回避的 —— 推理必然需要明文。

👉 完整说明与信任模型：**[`SECURITY.md`](../SECURITY.md)**

**因此：绝对不要在共用的 Swarm 里输入任何「你不愿意让其他所有运营者看到」的内容。**
密码、个人资料、医疗或财务信息、公司专有代码、未发表的研究 —— 都不要放进去。

## 4. 别人的 Prompt 会在你的 GPU 上执行

反过来也同样成立，而且很容易被忽略：

- **你无法控制其他参与者送进你硬件的是什么内容。** 那可能是冒犯性的、
  甚至在你所在国家是违法的内容。它会用**你的 GPU**、**你的电费**、
  在**你的 IP 地址**底下被处理。
- **你的硬件会被别人消耗。** 只要你的节点闲置到足以接受工作，就会产生耗电、发热与硬件损耗。
- 如果你的设备受到**学校或公司规范**限制可处理的内容，加入公开 Swarm 可能违反规定。请先确认。

## 5. 分享 `swarm.key` 就等于交出全部的安全边界

`swarm.key` 决定的是**谁能加入**，**不会**限制成员加入之后能做什么。
把密钥交给某人，就等于永久给了对方（直到你更换密钥为止）：

- 读取所有被分发到他手上的 Prompt 的能力
- 你的 IP 地址、硬件指纹与使用习惯
- 消耗你 GPU 的能力
- 把任意内容送进你硬件执行的能力

**请把「分享 `swarm.key`」视同「授予对方读取你用户数据的权限」** —— 因为实际效果就是如此。

分享密钥前请先自问：

- 我真的信任这个人**以及他机器的安全状况**吗？
- 如果他的机器被入侵、或他离开这个团队，会发生什么事？
- 我有更换密钥的计划吗？（更换密钥需要**同步更新每一个节点**。）
- 依照我所属单位的规定，我有权分享这把密钥吗？

## 6. 如果你使用的是公共或广泛流通的密钥

请假设**所有东西都会被陌生人看到**：

- ✅ 适合：性能测试、功能测试、公开／合成数据、用完即丢的测试 Prompt
- ❌ 不适合：个人信息、账号密码、客户或患者数据、公司专有内容、任何机密信息

另外请注意，仪表板（`:50007`）、API 网关（`:50006`）与 vLLM（`:8100`）**都没有身份验证**。
任何能连到你机器这些端口的人，都能使用你的 GPU、读取你节点的配置与日志。
**请勿将这些端口直接暴露在公开互联网上** —— 详见 [`SECURITY.md`](../SECURITY.md)。

## 7. 如果以上你无法接受 —— 你仍然可以使用这套软件

你**不需要**加入共用 Swarm 也能使用本项目：

- **单机独立运行。** 没有任何 Peer 的节点依然能用自己的 GPU 提供推理服务。
  不会分发任何请求出去，也不会对任何人广播。
- **建立私有 Swarm。** 密钥只分享给你或你的单位所掌控的机器。
  这样上述所有风险就都被限缩在你本来就接受的信任范围之内。

本文档所列的风险，**专指「与你无法掌控的人共用同一个 Swarm」的情境**。

## 重点总览

| 项目 | 状况 |
| :--- | :--- |
| 你的 IP、显卡型号、使用习惯 | 📡 每 3 秒广播给所有 Peer，并被 Hub 节点长期存储 |
| 你的 Prompt | ⚠️ 执行它的那个节点可完整读取 |
| 别人的 Prompt | ⚠️ 会在你的 GPU 上执行，内容不受你控制 |
| `swarm.key` | 🔑 只管「谁能进来」，进来之后就是完全受信任 |
| 仪表板／网关／vLLM 端口 | 🔓 完全没有身份验证 |
| 成熟度 | 🧪 实验阶段 —— 不提供任何形式的保证 |

**请勿通过你无法完全掌控的 Swarm，传送任何个人隐私或机密信息。**
